# Security policy

## Reporting a vulnerability

Use [GitHub private vulnerability reporting](https://github.com/theirishbrian/coded/security/advisories/new)
for suspected security vulnerabilities in Coded. Sign in to GitHub and use the
repository's Security → Advisories → Report a vulnerability flow. Private
vulnerability reporting was enabled and verified for this repository on 2026-09-22.

Do not open a public issue or pull request containing exploit details, credentials
or private data. Include the affected commit/version, impact, prerequisites and
minimal reproduction steps. Redact tokens and personal information; use synthetic
data wherever possible. Ordinary non-sensitive bugs belong in public issues.

If the private form is unavailable, open a public issue asking only for a private
reporting route, without vulnerability details. No security email address is
currently published. Do not use an unverified contact address.

## Support and handling

Coded is an unreleased application foundation. There are no supported release
lines or published security-update guarantees. Reports against the latest `main`
commit are welcome; include the exact commit tested. There is no response-time
commitment or bug-bounty programme.

The maintainer will use the private report to assess impact, discuss reproduction
and coordinate any fix and disclosure. Reporters should avoid sharing details
publicly while that discussion is ongoing. This policy does not authorise access
to other people's systems or data.
